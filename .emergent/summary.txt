<analysis>**original_problem_statement:**
The user wants to build a Lawn Bowls Tournament management application. The initial request was for a Skins based scoring system. The requirements evolved significantly to include:
- **Two user roles**: An **Organizer** to create tournaments and a special **Umpire** role to manage them.
- **Umpire Auto-Creation**: The system automatically creates an account with a temporary password for an umpire if they are not already registered.
- **QR Code Score Entry**: A single QR code is generated per round. Players scan this code to access a page where they can select their match and enter scores for both teams.
- **Umpire Verification**: The umpire views the player-entered scores on their dashboard, compares them with a paper scorecard, makes corrections if necessary, and then verifies the match to finalize the results.
- **Printable Scorecards**: For skins matches, the umpire can print/download A4 landscape scorecards with the QR code, showing two scorecards per page.
- **Advanced Standings**: Leaderboard ranking is based on skin points, then shot difference, then shots for.
- **Standard Scoring Mode**: The user then requested a second tournament type, Standard Scoring, to be selectable during tournament creation. This mode includes:
    - Configurable number of ends (12-21) and player formats (Singles, Pairs, Trips, Fours).
    - Singles matches ending when one player reaches 21 points.
    - Second round draw can be either Random or Strength vs Strength.
    - Winner is determined by match points (Win: 2, Draw: 1, Loss: 0), with ties broken by total shots and then shot difference.
